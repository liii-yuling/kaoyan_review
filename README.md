# 考研定制化复习系统

一个**纯前端、零依赖**的考研复习网页应用，覆盖 **英语一 / 数学一 / 信号与系统 / 政治** 四科。

核心是 **错题本 → 自动归类 → 按未掌握考点推题** 的闭环，外加 **英语一历年真题 + 逐题 B站详解** 和 **限时考试模式（自动判分）**。

数据全部保存在使用者自己的浏览器里，不上传任何服务器。

---

## 一、快速开始

### 方式 A（推荐，本地用）：双击 `启动.cmd`

会用本机 Node.js 起一个本地小服务并自动打开浏览器（地址形如 `http://127.0.0.1:8788`）。

> 用这种方式打开时，浏览器本地存储是正常工作的，**数据刷新后不会丢**。
> 注意：`127.0.0.1` 只对你自己这台电脑有效，**发给别人是打不开的**。

### 方式 B：直接双击 `index.html`

零安装、零依赖，双击就能用。

> 注意：部分浏览器在"直接打开本地文件"模式下会禁用本地存储，导致**刷新后数据丢失**。
> 页面左下角会明确显示当前是"本地存储正常"还是"临时存储模式"，看到临时模式请立刻到
> 「设置与备份 → 导出完整备份」存一份，或改用方式 A。

### 方式 C（要给别人用）：部署到免费静态托管 ★

**如果目标是"我更新、对方刷新就能用，而且我电脑关机也不影响他"，必须用这种方式。**
自己电脑上跑的服务做不到——`127.0.0.1` 只对本机有效，这是物理限制，不是配置问题。

一句话流程：

```
双击 发布.cmd  →  双击 推送.cmd  →  把网址发给对方
```

（不想用 git 的话，第二步换成"把 `dist` 里的内容拖进 GitHub 仓库网页"也行。）

以后每次更新：改完 → `发布.cmd` → `推送.cmd` → **对方刷新页面会出现「有新版本」提示条**，
点一下就是新版，她的错题本与掌握度不会丢。

**详细的每一步点击路径见 [`部署说明.md`](部署说明.md)**（含 GitHub Pages / Netlify / 腾讯云三方案对比）。

### 交付给别人用（离线方式，做不到"你更新他刷新"）

把整个 `kaoyan-review` 文件夹压缩发过去即可。对方：

1. 解压；
2. 有 Node.js 就双击 `启动.cmd`（推荐），没有就直接双击 `index.html`；
3. 进「设置与备份」填自己的姓名与考试日期。

**不需要任何安装、配置或联网**（图片 OCR 首次使用需联网下载语言包，见下）。

> 代价：这种离线方式**对方得重新收一次文件才能拿到更新**。
> 想要边更新边用，请用方式 C。

### 几个用起来才知道的设计

- **上传错题是"识别 + 人工核对"两步走。** 自动识别的考点和错因永远要你确认一遍再入库——
  OCR 一定有错字，规则引擎也一定有判偏见，你的修正比自动判定更准，而且**直接决定后面推题的准确度**。
- **答案跳转不是"藏起来"，是真的不渲染。** 题库/真题页答案默认收起，点按钮才展开；
  而**考试模式与练习作答中，答案块根本不会写进页面**，所以看网页源代码也偷不到答案。
- **一题多讲。** 同一道题可以绑多个老师的讲解视频，自己挑听得懂的那个。
  批量绑定支持「题目 ID 或题干关键词 + BV 号」，一行一个，也支持一行多个。
- **导入题库时"没有答案"会被拦下。** 这是硬规则，不是懒：判分、错题本、推题全都依赖答案。
  每行的问题都会写在预览列表里，告诉你错在哪，不会静默丢数据。
- **推题是可解释的。** 每道推送题下面都写着理由（"错题本里有 2 道「拉氏反变换」的错题" /
  "「多元极值」掌握度很低（18%）" / "2019 年真题"），不是黑箱。
- **错因判定分八类**（概念不清 / 公式记错 / 计算失误 / 审题偏差 / 方法思路 / 词汇术语 / 逻辑推理 / 粗心），
  因为"不会"和"马虎"的补救策略完全不同。掌握度报告里会单独提示哪一类占比过高。
- **多选题判分分两种模式。** 考试模式按考研真实规则（少选/多选/错选均不得分）；
  练习模式给部分分，方便看到"对了几项"。

## 【重要】两个人的分工（运营者 / 使用者）

这个站是按"一个人维护、一个人使用"设计的。

| | 运营者（你） | 使用者（她） |
|---|---|---|
| 主要页面 | **运营台** `#/console` | **今日计划** `#/plan` |
| 做的事 | 上传题库、写每日计划、挑错题推送、安排考试 | 按计划刷题、打勾、收下布置的错题、自己做模考 |
| 能看到对方的私人数据吗 | ❌ 看不到她的错题本/掌握度/成绩 | ❌ 看不到你的操作过程 |
| 怎么把东西给她 | 导出 → 覆盖到项目 → `发布.cmd` → 上传 dist | 刷新页面 → 点「立即刷新」 |

**三条"你 → 她"的通道**（都在运营台里，导出后跟代码一起发布）：

1. **共享题库**：你上传的题 → 她刷新就能刷到
2. **每日计划**：你手写每天的任务 → 她看到并逐项打勾
3. **错题推送**：你挑几道题 + 写一句提醒 → 她一键收进自己的错题本
4. **资料库**：你粘贴网盘链接（视频/讲义）→ 她按科目浏览、一键复制提取码

### ⚠️ 关于"加登录"这件事

站里有一个访问口令门（初始账号 `yxt123` / 密码 `yxt123`，
可在「运营台 → ⑤ 访问口令」里改）。但必须说清楚：

**它只能挡住"随手打开网址的人"（爬虫、误点链接的陌生人），挡不住会按 F12 的人。**

因为纯静态网站没有服务端，验证逻辑和源码全部公开，而且仓库是 Public。
同样，**纯前端的"注册"功能没有意义**——任何人都能注册，等于没门。

需要**真正的**访问控制，两条免费/低价路子：

| 方案 | 说明 |
|---|---|
| **Cloudflare Pages + Cloudflare Access** | 免费（50 用户以内），**真正的服务端鉴权**（邮箱验证码）。需要把站点从 GitHub Pages 迁到 Cloudflare Pages |
| 把仓库改成 Private | 需要 GitHub Pro（约 $4/月），**不再是免费的** |

详见 [`部署说明.md`](部署说明.md)。

### 数据为什么不是双向的

她的错题本、掌握度、打勾进度、考试成绩都在**她自己的浏览器**里。你这边碰不到。

这是"免费、不租服务器"的必然结果——没有数据库就没有双向同步。所以：

- 你想了解她的情况：让她到「设置与备份 → 导出完整备份」把 JSON 发给你，
  你在自己浏览器里「导入并合并」，就能看到她的全部数据；
- 你要给她东西：只能走上面三条"发布"通道。

这一点在运营台页面上也明确写了，避免误解。

## 四、数据规模（诚实说明）

| 科目 | 题量 | 其中标注年份的真题 | 板块覆盖 |
|---|---|---|---|
| 英语一 | 30 | 4（2013/2015/2017/2019） | 6/6 |
| 数学一 | 32 | 12（2011~2023） | 10/10 |
| 信号与系统 | 30 | 0（见下） | 7/7 |
| 政治 | 30 | 0（见下） | 5/5 |
| **合计** | **122** | **16** | 全部板块 |

**关于真题比例，有几件事必须说清楚，而不是含糊过去：**

1. **英语一的真题只有 4 道（占 13%）**，不是原计划的 40%~50%。原因是只有这 4 道的原文措辞与答案
   有十足把握；其余一律标为"模拟题（真题风格）"且不写年份。**宁可标模拟题，也不伪造真题出处。**
2. **信号与系统与政治没有逐题标注年份。** 这两科是自命题/记忆型科目，在没有可靠原始资料的情况下，
   标"某年某校第几题"等于编造。它们的来源如实写成"考研专业课真题风格题（校名与年份不可考）"
   和"考研政治 XX 模拟题（真题风格）"。其中确实有真题风格的题目，但没有冒充具体年份。
3. **英语一的"套卷"不是考场完整原卷。** 原卷每套 52 题 / 100 分，题库里每个年份只有 1 道题。
   所以系统把真题按**板块**汇编成一份《英语一历年真题 · 分板块精练卷》，
   而**不是**硬造出"2019 年真题卷（1 题）"这种没有意义的东西。
   后续往题库补题，套卷会自动变长（见第六节）。
4. **没有任何一个 BVID 是我编造的。** 每道题的 B站入口默认走**真实可点的搜索深链**
   （关键词按题目内容与考点自动生成）。真实视频链接会失效、会改标题，
   与其塞一堆可能 404 的假链接，不如让你绑定自己在看的视频，绑一次永久生效。

**这四条是取舍，不是遗漏。** 如果你能提供原始真题或答案，或者愿意放宽准确性要求，
补齐真题比例就是往题库里加数据的事，不需要改代码。

## 五、B站详解怎么用

1. 在真题墙/题库里，每道题答案默认收起。点题目下方的「**查看答案与详解 ↓**」，
   展开的答案块底部就是视频入口：
   - 未绑定时：点「去 B站看」跳到按该题内容自动生成的 B站搜索结果页；
   - 已绑定时：直接内嵌播放器，页面内就能看。
2. **单个绑定**：在 B站找到讲得好的该题讲解视频，复制地址栏的 `BV` 号，
   答案块里点「管理视频」粘贴进去。**一道题可以绑多个（一题多讲）**，一次可粘多个 BV 号。
3. **批量绑定**（手里已经有一批链接时用这个）：
   设置与备份 → 视频绑定管理 → **批量导入链接**。每行写：

   ```
   en1-2023-cloze-01 BV1xx411c7mD
   en1-2023-cloze-01 https://www.bilibili.com/video/BV1yy411c7mE
   信号与系统 拉普拉斯反变换 BV1zz411c7mF BV1aa411c7mG
   政治 对立统一规律 BV1bb411c7mH
   ```

   第一列可以是**题目 ID**，也可以是**题干关键词**（只在能唯一命中一道题时才生效，
   命中多道会提示你改用题目 ID）。点「先校验一遍」会逐行告诉你哪条能绑、哪条有问题。
4. 批量导入前可以先点「导出绑定列表」看看现有绑定，导出的是 CSV，题号与题干都在里面，
   方便你对着填链接。
5. 默认打开方式（题内就地播放 / 答案块里直接展开）可以在设置里切换。

## 六、怎么继续加东西

整个项目是经典脚本结构，模块之间只通过 `KY.<模块名>` 全局对象通信，
没有打包工具、没有框架耦合。**用记事本就能改。**

| 想做什么 | 改哪里 |
|---|---|
| **加题目（不碰代码，推荐）** | 「题库导入」页：下载 CSV 模板 → Excel 填题 → 上传 → 预览确认 → 导入。考点留空会自动归类 |
| 加题目（写进源码） | 按 `SCHEMA.md` 的格式，往 `src/data/bank.<科目>.js` 的数组里追加 |
| 加英语一真题套卷 | 只给题目加 `year` 字段就行，套卷自动汇编；带年份的题**通过导入进来也一样会自动进真题墙** |
| 绑定讲解视频 | 题目 →「查看答案与详解」→「管理视频」；批量绑定去「设置 → 视频绑定管理 → 批量导入链接」 |
| 加考点 | `src/data/taxonomy.js` 里对应模块的 `points` 数组，填上 `keywords` 特征词——分类引擎就认得它了 |
| 加新科目 | taxonomy 加一门 → 新建 `src/data/bank.新科目.js` → `index.html` 加一行 `<script>` 和一条导航 |
| 加新页面 | `src/ui/views/` 新建文件注册到 `KY.views` → `src/ui/app.js` 的 `registerRoutes()` 加一行 |
| 开 AI 增强 | 「设置 → AI 增强」填接口地址与 Key。开启后错题归类会在本地规则之上再走一次大模型纠错；**不开启也完全可用** |
| 开图片识别 | 「设置 → 图片识别」选本地识别或 API 视觉模型。本地识别免费离线，首次需联网下载约 15MB 语言包 |

### 改完代码后怎么让对方拿到新版
```bash
# 图形界面：双击 发布.cmd
# 命令行：
node tools/release.js --notes="这次改了什么"
```

`release.js` 会：先清出干净的 `dist/` → 给所有资源 URL 加上 `?v=<构建号>`（缓存击穿）
→ 写 `version.json` 与 `src/version.js` → 生成 `_headers` / `netlify.toml` / `vercel.json` / `.nojekyll`
→ 自检产物完整性。

然后把 `dist/` 里的内容上传到你选定的托管平台。对方刷新页面时，`update.js` 会比对
`version.json`，不一致就弹出「有新版本可用」提示条。**他的错题与掌握度存在浏览器里，不会丢。**

### 题库怎么更新到对方那边（共享题库）

题库分三层，合并优先级是 **内置题 > 共享题 > 个人题**：

| 层 | 在哪 | 对方能看到吗 | 怎么改 |
|---|---|---|---|
| 内置题库 | `src/data/bank.*.js` | ✅ | 改源码后发布 |
| **共享题库** | `src/data/bank.shared.js` | ✅ **刷新即得** | 导入页导出后发布 |
| 个人题库 | 浏览器本地 | ❌ 只有你自己 | 导入页直接导入 |

**关键点**：你在「题库导入」页点「导入这 N 题」，题只进了**你自己浏览器**，对方拿不到。
要让对方也拿到，必须走共享题库：

**路径 A（推荐）**

1. 「题库导入」页 → 上传题库 → 解析并预览
2. 点「**导出为共享题库文件**」→ 得到 `bank.shared.js`
3. 用它覆盖项目的 `src/data/bank.shared.js`
4. 双击 `发布.cmd` → 把 `dist` 里的内容重新上传
5. 对方刷新 → 顶部提示有新版本 → 点刷新，**新题库就到手了**

**路径 B（不用碰 src 目录）**

1. 「题库导入」页 → 点「导入 JSON 到项目根目录」→ 得到 `共享题库.json`
2. 把它放到项目根目录（和 `发布.cmd` 同一层）
3. 双击 `发布.cmd` —— 发布脚本会自动读它并打包进 dist

⚠️ **共享题的 id 不要和内置题重复**（建议统一加 `my-` 前缀）。重复的题会因内置优先而
**静默失效**——所以系统会在「题库导入」和「设置」页显式弹出红色警告列出冲突的 id，
发布脚本也会打印共享题库题数，方便你核对。

### 导入自己题库的最小步骤

1. 「题库导入」→「下载 CSV 模板」；
2. Excel 打开，一行一道题（模板里有 4 道示例，可删）；
3. **「答案」列必填**，「考点」列可留空；
4. 另存为「CSV UTF-8（逗号分隔）」；
5. 回页面点「解析并预览」→ 逐行核对 → 「导入这 N 题」。

详细的列说明见 `SCHEMA.md` 第 9 节。

改完记得跑一遍自检（下一节）。

## 七、自检命令

在项目根目录执行：

```bash
node tools/validate.js              # 题库与套卷格式校验（改完题库必跑）
node tools/smoke-test.js            # 核心流程自测：归类/推题/判分/套卷/导入/视频/更新检测/错题闭环
node tools/render-test.js           # 真实渲染测试：跑 boot() 并把 12 个路由全挂载一遍，抓白屏这类问题
node tools/render-test.js --dir=dist  # 同一套渲染测试，但针对发布产物（发布后必跑）
node tools/page-check.js            # 页面装配完整性：文件引用、加载顺序、路由与视图对应
```

`smoke-test.js` 会真的把浏览器模块跑在 Node 里，验证业务链路而不只是语法；
`render-test.js` 用一个够用的 DOM 桩真正执行启动流程——**白屏这类问题只有它会抓到**。

## 八、已知限制

| 限制 | 说明与应对 |
|---|---|
| OCR 对模糊截图 / 手写体效果有限 | 尽量用清晰的屏幕截图；或在设置里改用 API 视觉模型；实在不行直接粘贴文字，效果完全一样 |
| 错题自动归类会有偏差 | 入库前必须人工核对（这是设计如此）；入库后还能在错题详情里随时修正，改完推题跟着变 |
| 考点归类不准的常见原因 | 题干里特征词太少。把解析、选项也一起粘进去，命中率会明显提高 |
| 主观题无法真正自动判分 | 客观题自动判分；主观题交卷后按评分要点自评折算（作文/翻译/解答题都这样，任何系统都无法替代人评作文） |
| 导入题库必须每题都有答案 | 没答案的题在系统里无法判分、无法进错题本、无法推题，所以直接拦下并告诉你哪一行缺 |
| 数据存在浏览器本地 | 换浏览器、换电脑、清理浏览器数据都会丢。**每周导出一次完整备份**；导入的题库包含在备份里 |
| 部分考点没有对应题目 | 137 个考点中 110 个有题目覆盖。没覆盖的考点不会出现在推题里，补题即可 |
| 浏览器兼容 | 需要支持 ES5+ 与现代 DOM 的浏览器（Chrome / Edge / Firefox 近五年版本均可）。本地 OCR 需要 WebAssembly 支持 |

## 九、数据备份

- **导出**：设置与备份 → 导出完整备份（JSON，含错题本、掌握度、练习与考试记录、设置、视频绑定）
- **导入**：可选择「覆盖」或「合并」两种模式
- **错题本单独导出**：错题本页面右上角也有导出/导入，方便只迁移错题

建议每周导出一次，存到网盘或 U 盘。这是唯一可靠的防丢手段。
